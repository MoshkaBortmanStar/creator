---
description: "OpenSpec: кодогенерация по спеке и таскам изменения"
---

Пользователь запрашивает кодогенерацию для изменения: «$ARGUMENTS»
(аргумент — ID изменения: полный, префикс или номер).

Выполни по шагам:

1. `./openspec.py --list` — если ID не указан, покажи список
   изменений и попроси выбрать.
2. Прочитай `specs/<ID>/tasks.md` и покажи пользователю план: список задач
   одной строкой каждая. Спроси подтверждение.
3. После «да»: `./openspec.py --codegen --change <ID> --yes`
4. Прогони тесты проекта (команда — в `code_generation.test_command`
   конфига). Падения дожимай сам в TDD-стиле, ориентируясь на сценарии
   из `spec-bdd.md`.

**Флаг `--yes` обязателен.** Ты запускаешь команду без терминала, а без него
движок не может спросить согласие на запись и остановится с подсказкой.

**Не используй `--dry-run` по умолчанию.** Он вызывает модель точно так же,
просто не пишет файлы, — то есть полная стоимость генерации впустую.
Код и так пишется в отдельный worktree, а не в рабочую ветку, поэтому
посмотреть результат можно и после записи. Запускай `--dry-run` только если
пользователь прямо просит сначала взглянуть, не записывая.

Если генерация упёрлась в пустой ответ, движок сам дробит батч. Когда пусто
даже на одной задаче — он печатает, что менять; не повторяй ту же команду,
это потратит минуты без шанса на другой результат.
