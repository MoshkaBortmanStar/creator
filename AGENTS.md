# Инструкции агенту

## Правки файлов — точечные, а не переписывание

Always use strict line-level diffs or small SEARCH/REPLACE blocks.
NEVER rewrite the whole class or file if the change is local. Be concise.

Практически это значит:

- меняешь одну функцию — правь эту функцию, а не выводи файл целиком;
- добавляешь зависимость — вставляй строку, а не перепечатывай весь блок;
- перед правкой прочитай нужный фрагмент, а не файл от начала до конца;
- в ответе показывай только изменённые места, а не итоговое содержимое.

Причина не только в токенах. **При перепечатывании файла модель теряет
детали.** В проектах на этом конвейере так уже пропадали: обёртка темы
в корневом composable, цвета кнопок, префикс в именах артефактов сборки.
Каждый раз файл оставался синтаксически верным и собирался — ломалось
поведение, и находилось это не сразу.

Исключения, когда файл выводится целиком: создание нового файла, и правка,
затрагивающая больше половины содержимого.

## Кодогенерация движка следует тому же правилу

Раньше движок принимал только полные файлы, и это правило на него не
распространялось. Сейчас не так: его промпт требует блоков
`<<<<<<< SEARCH / ======= / >>>>>>> REPLACE` для всех существующих файлов,
а полное содержимое — только для новых.

То есть правило действует **везде**: и когда файлы правишь ты, и когда их
генерирует движок. Если видишь в выводе кодогенерации целиком
перепечатанный существующий файл — это дефект, а не норма.

## Не трогай без спроса

- `.openspec/` — submodule с движком. Правки там принадлежат репозиторию
  движка, а не этому проекту.
- `specs/` — артефакты конвейера. Их пишет движок; руками правят только
  спеки, и только осознанно.
